# Chapter2 思辨问答题参考答案

## 1. DMMF/F# 默认结构性相等；Elixir 通过 Protocol 实现业务上下文相等。DDD 什么时候不能直接使用原生相等判断？举业务案例。

### 核心结论

原生相等分为两种：引用相等、结构全字段相等。当**业务语义上的 “相等” 和内存 / 全字段对比不一致**时，不能直接使用原生判断。

1. **实体场景**：业务唯一标识是 ID，其他字段可以变更。两个对象字段不同、但主键一致，业务判定为同一个实体；全字段结构性相等会认为二者不相等，违背领域语义。
2. **多上下文判等场景**：对象有一套全局身份规则，同时多个业务流程需要临时、自定义的相等逻辑（FastPass 按时间判重复）。原生相等只能固定一套规则，无法灵活切换。

**业务案例**
游乐园快速通行证`FastPass`：

- 全局业务身份：id 相同 = 同一张凭证；修改预约时间，依然是同一个凭证
- 业务校验规则：同一个游客不能拥有两条**时间相同**的凭证
原生结构相等会把「id 一致、time 不同」的两条记录判定为不相等，不符合实体定义；同时原生语法无法临时切换成按时间判重。

## 2. Java Record 默认的 equals ()，什么时候需要重写自定义业务相等规则？和本章 Eq 协议设计思路对齐。

1. **Record 默认行为**：自动基于**全部字段做结构性相等判断**。适合值对象（Value Object），所有字段完全一致才等价。
2. **需要自定义 equals 的场景**
   - 领域实体：相等仅由唯一业务 ID 决定，忽略其他可变业务字段；
   - 原生全字段对比不符合领域业务语义。
3. **与本章 Eq 协议对齐**

> 
> 设计共识：**全局语义固化在类型内部；场景化比较逻辑外置，不侵入领域模型**
   - Record 重写`equals()` = **全局固定的领域身份规则**（对应协议默认实现）
   - `contramap` / `Comparator` / `distinctBy` = **外置、上下文专用的比较器**，不修改 Record 本身 equals，按需注入临时判断逻辑

> 
> 最佳工程实践：实体重写 equals/hashCode 基于主键；值对象直接复用 Record 默认实现；临时业务比较全部使用外部 Comparator，不修改类型本身。

## 3. 领域唯一性校验（例如 Slug 唯一），可插拔 Eq 协议能给业务校验带来什么灵活性？

1. **一套校验逻辑，多套判等策略复用**
唯一性校验工具本身不用改动，通过传入不同的 Eq 比较规则，切换判断维度：
   - 按完整 slug 字符串校验全局唯一
   - 忽略大小写校验重复别名
2. **解耦校验逻辑与领域对象**
领域实体不需要硬编码各种重复判断逻辑，校验规则作为独立组件，UseCase 按需注入。
3. **测试友好**
单元测试可以替换轻量自定义比较规则，不需要修改生产领域代码；
4. **业务迭代成本更低**
未来新增一种去重规则（例如忽略后缀数字），只需要新增一个比较器，不需要改动原有实体和校验骨架代码。

**举例**：文章 Slug 校验

- 默认：完整字符串相等判定重复
- 新需求：忽略末尾自增数字判定冲突；仅新增一个 contramap 比较器，校验函数完全复用。

## 4. 集合去重、匹配判断场景，Eq 抽象在 Domain 层如何减少重复的 if‑else 判断？

1. **策略模式封装判断逻辑**
把各种各样的业务相等判断（按 id、按时间、按别名）封装成独立的比较组件，不再散落在业务代码大量`if/else`；
2. **通用集合工具只依赖抽象 Eq 契约**
`uniq`、`findDuplicate`这类通用领域工具只接收比较器作为参数，不需要为每一种业务场景单独写一套循环判断逻辑；
3. **消除重复样板代码**
不再每个 UseCase 手写一遍遍历‑对比‑判重的循环模板；业务代码只需要选择对应的比较器，调用通用工具；
4. **规则可组合、可复用**
同一个时间比较器，可以同时用于「集合去重」、「重复校验」、「列表匹配过滤」多个业务场景，逻辑只定义一次。

**通俗总结**：把**“怎么算相等”**从业务流程中抽离成为独立参数，业务代码只关心**“要不要去重”**，判断规则外部传入，消灭大量重复的条件分支。

# 整体章节核心思想总结

1. 区分两套语义：**实体全局身份相等** 和 **业务上下文临时相等**
2. 全局规则定义在领域模型内部；上下文比较逻辑外置，通过 contramap 动态构造
3. 相等策略作为可插拔组件，通用领域工具依赖抽象，实现逻辑复用，减少样板判断代码
4. Java 落地：`equals()`负责全局身份；`Comparator`/`distinctBy`负责场景化临时比较
